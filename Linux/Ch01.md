
# Chapter 1: Getting Started with Linux 

> Source: *Practical Linux System Administration* by Kenneth Hess (O'Reilly, 2023) 

## 1. Chapter Overview 

- **Linux system administration** means the daily actions a sysadmin takes to manage and support users, maintain system health, apply security best practices, install software, and perform housekeeping. 
- This chapter covers **installing Linux, initial setup, and exploring the system with simple shell commands**. 
- Sysadmins spend much of their time at the **command-line interface (CLI)**. GUIs are rarely installed or used on servers. 

--- 

## 2. Installing Linux 

- There is no single correct way to install Linux, only guidelines. 
- For junior sysadmins, installation usually happens through **automated means** such as **Kickstart** or another enterprise delivery system. 

### 2.1 Preparing Your System 

- **If this is your first install, use a virtual machine (VM).** 
 - You don't dedicate a whole machine to a learning system. 
 - You avoid the risk of breaking your current system (as with multiboot setups, which are out of the book's scope). 
- **VirtualBox** lets your computer act as a **VM host** with Linux running as a **guest OS**. 
 - The host can be Windows, Mac, or Linux, and the host and guest OS can differ. 

### 2.2 Choosing a Distribution and Installing 

Pick the distro your employer uses. If you have no preference, popular choices are: 

| Distro | Key points | 
|---|---| 
| **Debian** | Top-level distro from which many others derive. Community-supported, open source, free. | 
| **OpenSUSE** | Community-supported top-level distro. Its commercial version is SUSE Linux Enterprise. | 
| **Red Hat Enterprise Linux (RHEL)** | Commercially supported, widely adopted in enterprises, now owned by IBM. | 
| **Ubuntu** | Very popular, Debian-derived, with community and commercial support. Offers ready-made VirtualBox VMs. | 

The downloaded **ISO file** is a bootable Linux image. You don't need to modify it; the VM boots from it to start installation. 

**Attaching the ISO in VirtualBox:** 

1. Configure your VM, then open **Settings** in the Oracle VM VirtualBox Manager. 
2. Select **Storage**. 
3. Select the empty optical drive under the IDE controller. 
4. In the Attributes pane, click the optical disk icon and browse to your ISO. 
5. Click **OK**, then start the VM. It boots from the ISO and begins installation. 

**During installation:** 

- You can accept the default settings (change them if you have experience). 
- Create a **user account** when prompted. 
- If prompted, set a **root password** and **remember it**. Without it you must reinstall or attempt recovery. 
- Installation takes several minutes and ends with a **reboot**.

## 3. Getting to Know Your New Linux System 

- After installation, log in with the credentials you created. You land in your **home directory** inside a shell. 
- The Linux filesystem is **hierarchical**, like Windows. 
- **Windows vs. Linux:** 
 - Windows can have many roots (`C:`, `D:`, `E:`). 
 - Linux has **only one root directory, `/`**, and everything else is a subdirectory of it. 

### 3.1 The Linux Directory Tree 

``` 
/ 
├─ bin ├─ dev ├─ etc ├─ home ├─ lib ├─ media 
├─ mnt ├─ opt ├─ proc ├─ root ├─ run ├─ sbin 
├─ srv ├─ sys ├─ tmp ├─ usr └─ var 
``` 

- Under `/` there are **only directories**, not individual files (some distros have a few symbolic links). 
- **All files live inside directories.** 

### 3.2 Table 1-1: What Each Directory Holds 

| Directory | Description | 
|---|---| 
| `/` | Root filesystem. Contains only other directories. | 
| `/bin` | Executable binaries. Points to `/usr/bin`. | 
| `/dev` | Device files for addressing peripherals. | 
| `/etc` | **System configuration files** for users and services. | 
| `/home` | Users' home directories. | 
| `/lib` | System libraries. Points to `/usr/lib`. | 
| `/media` | Mount point for media such as USB drives or DVDs. | 
| `/mnt` | Mount point for mounting remote filesystems. | 
| `/opt` | Third-party software installs here. | 
| `/proc` | Virtual filesystem that tracks system processes. | 
| `/root` | The root user's home directory. | 
| `/run` | Variable, volatile runtime data. | 
| `/sbin` | System binary (executable) files. | 
| `/srv` | May contain data from system services. | 
| `/sys` | Kernel information. | 
| `/tmp` | Session information and temporary files. | 
| `/usr` | Programs and libraries for users. | 
| `/var` | Variable files such as logs, spools, and queues. | 

### 3.2 Key Rule: System Files Are Protected 

- Only the **root (administrative) user** can modify system configuration files and settings. 
- Regular users generally have write access only to: 
 - their own **home directory** 
 - **`/tmp`** 
 - **shared directories** created by the administrator

## 4. Learning the CLI 

- The **CLI** is how most sysadmins interact with Linux, since servers typically have no graphical interface. 
- Windows analogy: a CLI-only Linux server is like **Windows Server Core**. 

### 4.1 stdin, stdout, stderr 

| Term | Meaning | 
|---|---| 
| **stdin** (standard input) | Keyboard input (can also be file redirection or programs). In this book it means keyboard. | 
| **stdout** (standard output) | A command's normal output to the screen. | 
| **stderr** (standard error) | An error message from the system. | 

- You should **commit a few commands and options to memory** rather than looking them up, so your work becomes natural and efficient. 

### 4.2 Six Things to Know About Linux 

1. **Linux doesn't use file extensions.** `filename.exe`, `Financial_Report.txt`, and `Résumé.doc` are all just files and may or may not be executable or text. 
 - Use whitespace in filenames with caution, since it requires quotation marks. 
2. **Filenames are case-sensitive.** `filename.txt` and `filename.TXT` are two different files. 
3. **A file's permissions** determine whether you can execute, edit, or even read it. 
4. **Every location is uniquely named by its path from root (`/`).** For example, the password file is `/etc/passwd`. This is the **absolute path**. 
5. **Linux assumes you know what you want and spelled everything correctly.** Some actions are irreversible, so spelling counts. 
6. **Linux is not "chatty."** It doesn't ask "Are you sure?" before deleting files. 

> If you've used the Windows Command Prompt (cmd) or PowerShell, the Linux CLI will feel familiar. 

### 4.3 `pwd` (print working directory) 

- Shows where you are in the filesystem. 

```bash 
$ pwd 
/home/student1 
``` 

- `$` is the shell prompt and indicates you're logged in as a regular user. 

### 4.4 `cd` (change directory) 

- Moves you into a new directory, back to your home directory, up a level, or into a subdirectory. 

```bash 
$ cd /etc 
$ pwd 
/etc 

$ cd # plain cd always returns you to your home directory 
$ pwd 
/home/student1 
``` 

- Use the **absolute path**: `cd /usr/bin` 
- From a parent directory you can use a relative path: 

```bash 
$ cd /usr 
$ cd bin 
$ pwd 
/usr/bin 
``` 

- You'll use `cd` every time you connect to a Linux system. 

### 4.5 `ls` (list) 

- Lists files and directories. With no location given, it lists the **current directory**. 

```bash 
$ ls /usr/bin # list a specific directory 
``` 

- A new home directory shows no visible files at first. 
- **Hidden files** have names that begin with a period (`.`). Use the **`-a`** option to see them: 

```bash 
$ ls -a 
. .. .bash_history .bash_logout .bash_profile .bashrc .gnupg .zshrc 
``` 

- You can `cd` into hidden directories and list their contents: 

```bash 
$ ls .gnupg 
private-keys-v1.d pubring.kbx 
```

## 5. Starting, Rebooting, and Shutting Down 

**Why it matters:** Powering off without a shutdown command is bad because it can: 

- corrupt open files 
- leave files in an "open" state 
- disrupt running services 
- damage database transaction logs, possibly causing **data loss** 

### 5.1 Starting a System 

- On a physical system, press and release the power button. This begins the **power-on self-test (POST)** and boot process. 
- **Watch the console during boot.** The system notifies you of issues and logs them as it starts. 
- The worst message you can see is a **kernel panic** (covered later in the book). 
- A healthy boot ends with a login prompt. 
- Startup can reveal **systemic problems** with memory, disk, filesystem, and network. Note any issues for later investigation. 

### 5.2 Restarting (Rebooting) 

- Rebooting is a **standard sysadmin practice**, and there's nothing wrong with doing it regularly. 
- Benefits: it **clears memory**, **refreshes connections**, and confirms the system is healthy. 
- A reboot can cure certain nagging problems (such as an application that drains memory), but only **temporarily**. 
- Investigate anything a reboot resolves **once the system is up and stable**, so you don't need another reboot later. 

### 5.3 Shutting Down 

- Shutdown is a command that **gently** closes all programs and eventually powers off the system. 
- It **warns shell users** so everyone can save their work and log off. 
- Reserve shutdown for: 
 - **hardware maintenance** 
 - **relocation** 
 - **decommissioning** 
- Some enterprise policies require a **full shutdown once a year** to surface hardware issues that only appear after a complete failure. Technicians often do hardware maintenance and checks at the same time.
