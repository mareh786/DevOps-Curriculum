# Chapter 3: Customizing the User Experience 

> Source: *Practical Linux System Administration* by Kenneth Hess (O'Reilly, 2023) 

## 1. Chapter Overview 

- Sysadmins are often asked to make small changes to **one user's environment** or to the **default environment for all users** (a **global change**). 
- Such changes are fine as long as they **don't compromise system security or violate corporate policy**. 
- Your duty is to the **company first, then the user**. The user is your customer. 
- Global defaults can be **overridden** by users. Example: in Chapter 2, setting your own `umask` in `~/.bashrc` superseded the system's global umask. 
- This chapter covers: 
 - The key **hidden files in each user's home directory** 
 - Their **global counterparts** under `/etc` 
 - The `/etc/skel` directory 
 - **Customizing the shell prompt** 

--- 

## 2. Altering Home Directory Options 

- A few **hidden files** in each user's home directory control most of the user's environment. 
- The chapter focuses on **bash**, the most common shell. Other shells (ash, zsh, csh, ksh) have similarly named and structured files. 
- You may have to make changes **on the user's behalf**, since some users lack the skills. 

### 2.1 Files You Will Work With 

| File | Purpose | 
|---|---| 
| `.bashrc` | Functions, aliases, PATH | 
| `.bash_profile` | Login-shell-only customizations | 
| `.bash_logout` | Runs at logout | 
| `.profile`, `.bash_login` | May exist depending on distro and prior configuration | 
| `.bash_history` | A log of issued commands. **No changes needed**, nothing to configure. | 

### 2.2 Order of Execution (Interactive Login) 

When you log in interactively, the files run in this order: 

1. `/etc/bashrc` (global) 
2. `/etc/profile` (global, which also calls `/etc/bashrc`) 
3. `~/.bashrc` 
4. `~/.bash_profile` 
5. `~/.bash_logout` runs **at logout** 

> The book's summary says `.bashrc` executes first, then `.bash_profile`. The per-file sections below describe the full sequence including the global files. 

> **Warning:** Be careful what (and how many) programs, scripts, and messages you put in startup files. If they're corrupt, damaged, or half open, your login may be **delayed or impossible**, and another sysadmin will have to rescue you. Pass this warning on to your users.

## 3. Login vs. Nonlogin Shells 

| Type | What it is | 
|---|---| 
| **Interactive login shell** | You SSH in or log in directly with a username and password or SSH key. | 
| **Interactive nonlogin shell** | A child shell you start from the command line (for example, by typing `bash`). | 

- `$SHLVL` is a variable that tracks the **shell level**. 
 - First login: `$SHLVL` = **1** 
 - Each child shell increments it 

```bash 
$ bash 
$ echo $SHLVL 
2 
``` 

- A child shell is **interactive but nonlogin**, because it doesn't involve a new login.

## 4. The Global Files 

### 4.1 `/etc/bashrc` 

- The **first personalization file** to run on interactive login. It also runs for **interactive nonlogin shells**. 
- A **global** file providing **functions and aliases** to bash. 
- **Leave it as is.** Even as a sysadmin, don't edit it. The file itself warns: 
 - It's not a good idea to change it unless you know what you're doing. 
 - Better to create a **`custom.sh` script in `/etc/profile.d/`**, which avoids merge problems with future updates. 
- Its **user-level analog** is `~/.bashrc`. Change functions and aliases there. 

### 4.2 `/etc/profile` 

- A **system-wide startup file**. It provides generic **variables, paths, and settings** to all users. 
- Carries the same warning: use **`/etc/profile.d/`** for customizations. 
- Global settings **can be overridden** by files in the user's home directory. 
- It's the **second** file to execute on login. It also calls `/etc/bashrc`, so `/etc/bashrc` ends up **executing twice**. 
- Its **user-level analog** is `~/.bash_profile`. Change environment settings there.

## 5. The User-Level Files 

### 5.1 `.bashrc` 

- A hidden file in the home directory. It's hidden so that wildcard rename or delete operations don't touch it. 
- You have **full ownership** and can edit it freely. 
- Used for **functions** and **aliases**. 
- Executes **after the global files**, and also runs in **interactive nonlogin shells**. 
- **Augment or change `PATH` here** so the shell behaves the same for login and nonlogin instances. 

Default content: 

```bash 
# .bashrc 

# Source global definitions 
if [ -f /etc/bashrc ]; then 
 . /etc/bashrc 
fi 

# User specific environment 
if ! [[ "$PATH" =~ "$HOME/.local/bin:$HOME/bin:" ]] 
then 
 PATH="$HOME/.local/bin:$HOME/bin:$PATH" 
fi 
export PATH 

# Uncomment the following line if you don't like systemctl's auto-paging feature: 
# export SYSTEMD_PAGER= 

# User specific aliases and functions 
``` 

**Aliases** are shortcuts to commands and their options. Because Linux isn't "chatty," you can add safety prompts: 

```bash 
alias rm='rm -i' 
alias cp='cp -i' 
alias mv='mv -i' 
``` 

- `-i` means **interactive**: it asks for confirmation before acting. 
- Especially handy for destructive commands such as `rm`: 

```bash 
$ rm file4.txt 
rm: remove regular empty file 'file4.txt'? 
``` 

- Another useful alias, for long listings: 

```bash 
alias ll='ls -l' 
``` 

- You can also create aliases **per session**: run `alias` at the command line without saving it to a file. It lasts until you log off or end the shell. 
- Many sources recommend putting **all customizations in `.bashrc`**, since it runs for both login and nonlogin shells. This guarantees **shell consistency**. 

### 5.2 `.bash_profile` 

- The **last file to execute** on an interactive login. 
- Customizations here run in **interactive login shells only**, not in nonlogin shells. 

Default content: 

```bash 
# .bash_profile 

# Get the aliases and functions 
if [ -f ~/.bashrc ]; then 
 . ~/.bashrc 
fi 

# User specific environment and startup programs 
``` 

### 5.3 `.bash_logout` 

- Executes **on logout**. It's **optional**. 
- Lets users **clean up temporary files** on exit. 
- Can also be used to **log shell time** or **send a message** at logout.

## 6. The `/etc/skel` Directory 

- A **special directory** holding files you want **every new user** to receive in their home directory. 
- Files are **copied during account creation**. They don't have to be hidden, although the defaults are. 
- These are the **global copies** of the environment personalization files. 

Default `/etc/skel` contents on Red Hat Enterprise Linux–based systems: 

``` 
-rw-r--r--. 1 root root 18 Apr 21 10:04 .bash_logout 
-rw-r--r--. 1 root root 141 Apr 21 10:04 .bash_profile 
-rw-r--r--. 1 root root 376 Apr 21 10:04 .bashrc 
-rw-r--r--. 1 root root 658 Mar 3 2020 .zshrc 
``` 

**Key points:** 

- A file you add to `/etc/skel` goes to **new users only**. 
- **Existing users do not receive** files added afterward. You must **copy them manually** to each home directory and **fix permissions** so the user has full control. 

> **Tip:** Linux has a local help system called **man pages**. Use `man <keyword>`, for example `man ls`. You can navigate them with vi (Vim) commands.

## 7. Customizing the Shell Prompt 

- Most users accept the default prompt: 
 - Generic form: `[username@hostname pwd]$` 
 - Example: `[khess@server1 ~]$` 
 - `~` represents the user's **home directory** (that's why files appear as `~/.bashrc` and `~/.bash_profile`). 
- The prompt is stored in the **`PS1`** environment variable. 
- Default value: 

```bash 
PS1="[\u@\h \W]\\$ " 
``` 

- The system sets it in **`/etc/bashrc`**. You can **override it in `~/.bashrc`**. 

### 7.1 Table 3-1: Backslash-Escaped Prompt Characters 

| Code | Meaning | 
|---|---| 
| `\a` | ASCII bell character (07) | 
| `\d` | Date in "Weekday Month Date" format (e.g., "Tue May 26") | 
| `\D{format}` | Format passed to `strftime(3)`. Braces required. An empty format gives a locale-specific time. | 
| `\e` | ASCII escape character (033) | 
| `\h` | Hostname up to the first `.` | 
| `\H` | Full hostname | 
| `\j` | Number of jobs currently managed by the shell | 
| `\l` | Basename of the shell's terminal device name | 
| `\n` | Newline | 
| `\r` | Carriage return | 
| `\s` | Name of the shell (basename of `$0`) | 
| `\t` | Current time, 24-hour `HH:MM:SS` | 
| `\T` | Current time, 12-hour `HH:MM:SS` | 
| `\@` | Current time, 12-hour am/pm | 
| `\A` | Current time, 24-hour `HH:MM` | 
| `\u` | Username of the current user | 
| `\v` | Bash version (e.g., 2.00) | 
| `\V` | Bash release (version + patch level) | 
| `\w` | Current working directory, with `$HOME` shown as `~` | 
| `\W` | Basename of the current working directory, with `$HOME` shown as `~` | 
| `\!` | History number of this command | 
| `\#` | Command number of this command | 
| `\$` | `#` if the effective UID is 0 (root), otherwise `$` | 
| `\nnn` | Character matching octal number `nnn` | 
| `\\` | A backslash | 
| `\[` | Begin a sequence of nonprinting characters (e.g., terminal control sequences) | 
| `\]` | End a sequence of nonprinting characters | 

- Some users build **colorful or artistic prompts** (the book shows a Christmas-themed one). Search online for "fun Linux prompts." 
- To reset: **log out and back in**, or run: 

```bash 
PS1="[\u@\h \W]\\$ " 
```

## 8. Quick Revision 

| Topic | Key point | 
|---|---| 
| Global vs. user files | `/etc/bashrc` is analogous to `~/.bashrc`; `/etc/profile` is analogous to `~/.bash_profile` | 
| Which to edit | Edit the **user-level** files, or add scripts under `/etc/profile.d/`. Don't edit the global files directly. | 
| Execution order (login) | `/etc/bashrc` → `/etc/profile` → `~/.bashrc` → `~/.bash_profile` → `~/.bash_logout` at exit | 
| `/etc/bashrc` | Functions and aliases. Runs in login and nonlogin shells. | 
| `/etc/profile` | Variables and paths. Calls `/etc/bashrc` (so it runs twice). | 
| `.bashrc` | Aliases, functions, PATH. Login and nonlogin shells. | 
| `.bash_profile` | Login shells only. Sources `.bashrc`. | 
| `.bash_logout` | Optional cleanup at logout | 
| `.bash_history` | Command log. Nothing to configure. | 
| `$SHLVL` | 1 at login; increments for each child shell | 
| `/etc/skel` | Template files copied to **new** accounts only | 
| Alias safety | `alias rm='rm -i'` (also `cp`, `mv`) | 
| Prompt variable | `PS1`, set in `/etc/bashrc`, override in `~/.bashrc` | 
| Startup file risk | Bad content can delay or block login |
